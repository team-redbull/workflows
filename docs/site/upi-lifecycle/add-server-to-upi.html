add-server-to-upi — what actually happens

You name a UPI cluster and a server. The run takes the server from server-scan, picks two link-UP NICs for bond0, builds an oc adm node-image create ISO with the cluster's VLAN on the bond (DHCP), boots it through the BMC's Redfish virtual media, approves the host's CSRs and ends when its Node is Ready. What the runbook did by hand, and what cluster-expender tried as a CLI.

The run, step by step

From a server's name to a Ready Node

Each card carries a phase, read live through the run's progress query on GET /workflows/runs/{workflow_id}.

1

find_cluster_allocation

phase resolving-network

The cluster's node segment in the Segments Manager — its MCE one, else its UPI one — on the segment-lifecycle queue: the VLAN for bond0.<vlan>. A segment that says dhcp: false is SegmentWithoutDhcpError; none is UpiNetworkNotFoundError. Nothing allocated yet.

2

allocate_upi_server

phase allocating-server

server-scan's POST /servers/available for the named server: locked for the run (holder add-server-to-upi, 4 h), live-checked, its BMC and interfaces[] returned.

3

select_bond_members (pure)

phase selecting-bond

add-server-to-mce's policy, reused: two link-UP NICs on two distinct physical ports (never two NPAR partitions of one wire), nic1 the first. A BMC driven over IPMI (no virtual media) is VirtualMediaUnsupportedError, an unknown one UnknownBmcVendorError, no bond NoBondableInterfacesError — each gives the lock back first.

4

inspect_upi_node

phase checking-cluster

A Node of that hostname already Ready: the server is in (a re-run) — straight to finishing.

5

build_node_iso

phase building-iso

On the cluster's upi-server worker: the host's nodes-config.yaml — nic1/nic2 bound to their MACs, bond0 (802.3ad by default) over them, bond0.<vlan> on DHCP, the install disk — and oc adm node-image create. The ISO lands in the worker's ISO volume as <hostname>.iso next to the config's hash: the same config is never built twice.

OCoc adm node-image create --dir … (as the worker's ServiceAccount)
6

boot_from_virtual_media

phase booting

Redfish, discovered not hard-coded: the system (server-scan's path, else the first), the manager's CD/DVD virtual media; whatever else is mounted is ejected, the ISO (ISO_BASE_URL/<hostname>.iso, served by the worker's nginx sidecar) inserted and read back, a one-time boot to CD, then On or ForceRestart.

HTTPSthe BMC's Redfish API, with the worker's per-vendor credentials
7

await_node_joined

phase joining

Every 15 s, approves only this host's CSRs — the node-bootstrapper client CSR whose subject is system:node:<hostname>, and the serving CSR requested by that node — until the Node is Ready. join_timeout_minutes (90) bounds it: NodeJoinTimeoutError.

8

finish_upi_node · extend_upi_server_lock

phase finishing

The Node's node_labels (read back), the media ejected and the ISO deleted (both best effort, noted); server-scan's lock extended to a day so the server is not drawn again before server-scan sees it in the cluster.

One server a run; several servers are several requests (their runs go in parallel). The cluster's upi-server-worker must be deployed in it (deploy/charts/upi-server-worker), or the run waits, visible as a pending activity.

Failures

  • UpiNetworkNotFoundError, SegmentWithoutDhcpError — before anything is allocated.
  • ServerNotAvailableError, ServerScanAuthError, AmbiguousServerNameError, ServerReservedError — server-scan's answers.
  • UnknownBmcVendorError, VirtualMediaUnsupportedError, NoBondableInterfacesError — the lock is given back.
  • NodeImageBuildError — oc's stderr in the message. BmcCredentialsMissingError, RedfishAuthError, VirtualMediaUnavailableError — the BMC.
  • NodeJoinTimeoutError — the Node's last state and the CSRs approved; look at the server's console.
  • After the allocation, a failure LEAVES the lock to its 4 h TTL and undoes nothing (half-done work may still name the machine).

Run it again

The same server and cluster: the ISO is reused when its config is the same, and a Node already Ready skips straight to finishing. A cancel undoes nothing.

Dependencies

  • upi-server-worker, one per UPI cluster, inside it: its ServiceAccount (cluster-admin by default, for node-image), server-scan's ADMIN token, the BMC credentials per vendor, the ISO volume and its nginx sidecar + Route.
  • segment-lifecycle-worker: the cluster's node segment.
